# OCTAVE - Session Master Context

## 1. Session Objective & Operating Protocol
- **Primary Objective**: Deliver a refined, rock-solid user experience for OCTAVE. For each function, feature, or UI page named by the user, conduct a deep inspection for bugs, state integrity, performance bottlenecks, race conditions, WinUI 3 quirks, edge cases, and UX polish.
- **Continuous Tracking Protocol**:
  - Keep `repo_context.md` updated with any systemic or architectural changes.
  - Keep `session_master_context.md` (this file) strictly updated after every inspection, bugfix, or optimization to maintain continuous state, prevent hallucination or context loss across long conversations.
- **Golden Rule**: Think twice before making any changes. Make sure that it does not create any new bugs/issues. Play safe.

---

## 2. Review Checklist for Each Named Component
When the user names a component, feature, or page, systematically evaluate:
1. **Functional Correctness & Bug Audit**: Logic errors, off-by-one errors, nullability, missing state updates, edge-case handling.
2. **Integrity & Concurrency**: Thread safety (UI Dispatcher vs ThreadPool / BASS callbacks), lock ordering, race conditions, async cancellation.
3. **WinUI 3 & XAML Robustness**: SelectionMode COM safety, RangeBase clamp safety, layout thrashing, virtualizing panels, theme resources, visual states.
4. **Performance & Memory**: Unnecessary re-renders, redundant database/disk queries, event handler leaks, image allocation / caching.
5. **UX & Polish**: Visual consistency, animations, empty states, error feedback, accessibility, fluid transitions.
